# Design

**One file, one Dict per job.** `src/tokenizers/tokenizer.mojo` holds the loader, both models and decode. `src/json` parses the file
into a flat node array and the loader walks it without building a document tree; `src/uregex` runs the pre-tokenizer pattern
(`\p{L}`, lookahead `\s+(?!\S)`, `(?i:...)`, `\p{N}{1,3}` are all it needs). Both are vendored unedited (`docs/vendored.md`).

**BPE.** A merge `a b` becomes one `Dict[Int, Int]` entry: key `(id(a) << 32) | id(b)`, value `(rank << 32) | id(ab)`. No strings are built
while merging. A pre-token starts as one id per byte (a 256-entry table), then a binary min-heap of `(rank << 32) | position` plus a
linked list of live symbols merges lowest rank first, leftmost on ties, in O(n log n). A stale heap entry is detected by re-reading the
rank of the pair now at that position. `ignore_merges` (Llama 3) looks the whole piece up in the vocabulary first. Finished pieces are
cached by their text (cleared at 200,000 entries).

**Pre-tokenizer pipeline.** `Split(Regex, Isolated)` keeps the matches and the text between them; `Split(Removed, invert)` keeps only the
matches; `ByteLevel(use_regex)` adds the GPT-2 pattern. Added tokens are cut out of the text before any of this, longest first.

**WordPiece.** `BertNormalizer` runs per code point in the crate's order (clean, CJK spacing, strip accents, lowercase). The Unicode data it
needs (control and punctuation ranges, canonical decompositions without marks, lowercase maps) is generated by `tools/gen_bert.py` from
the oracle Python (Unicode 16.0.0) into `src/tokenizers/bert_tables.mojo`, 41 KB, so nothing is read at run time but two small dicts
built at load. Hangul syllables decompose in code. Unassigned code points are kept, as the crate keeps them (found by the gate).

**Memory.** Peak RSS is the vocabulary: 26 MB (BERT), 35 MB (GPT-2), 61 MB (Qwen2.5), 76 MB (Llama 3) while encoding 1 MB, against the crate's
34, 42, 84, 109 MB in Python. The file is read once, parsed in place and freed after load.
